## Validation rubric

- [x] The attacker has no vault shares before the default and physical delivery.
- [x] The vulnerable path is permissionless after `redeemOrder()` records bad debt.
- [x] Fresh shares can be minted and consumed by `dealBadDebt()` atomically.
- [x] A counterfactual branch proves the same collateral was claimable by the pre-default LP.
- [x] The collateral oracle value exceeds all attack capital without valuing residual attacker shares.

## Root cause

Four accounting choices compose into the exploit:

1. `OrderManagerV2.redeemOrder()` records `badDebt` and leaves delivered collateral in the vault.
2. The recognized bad debt is not removed from `_accretingPrincipal`, so `totalAssets()` still counts it at face value.
3. `deposit()` and `mint()` remain available while bad debt and recovery collateral are outstanding.
4. `dealBadDebt()` uses the current ERC-4626 share price and current share owner. It does not snapshot the supply or holders that funded the position before default.

Consequently, shares minted after the recovery outcome is known are accepted as payment for collateral generated by pre-default capital.

## Atomic attack

```text
1. A vault order reaches physical delivery.
2. redeemOrder() records bad debt B and receives collateral C.
3. The attacker observes B and C on-chain.
4. In one transaction, an attacker contract:
   a. mints fresh vault shares using approximately B asset tokens;
   b. immediately calls dealBadDebt(B);
   c. receives all C.
5. The original LP keeps the same share count but can no longer claim C.
```

The vault's transient action guard protects deposit-versus-withdraw combinations. It does not cover `dealBadDebt()`, so `mint()` and `dealBadDebt()` compose in the same transaction. Even a same-transaction restriction alone would not fully fix the issue because the attacker could mint in an earlier transaction after default.

## Economic proof independent of unrelated market liquidity

Let:

- `R` be debt-token reserves backed by matched FT/XT pairs;
- `D` be an unpaid borrower's FT debt;
- `F` be the vault order's FT balance;
- `V` be the oracle value of the unpaid borrower's delivered collateral;
- `p = F / (R + D)` be the order's share of redemption.

At physical delivery:

```text
debt tokens received = pR
bad debt B            = F - pR
                      = FD / (R + D)

collateral value      = pV
                      = FV / (R + D)
```

Therefore:

```text
collateral value / bad debt = V / D
```

The ratio is independent of `R` and `F`. Unrelated market liquidity cannot remove the exploit; it only scales the absolute amounts.

The first-party fixture creates:

```text
D = 1,000 debt tokens
V = 2,000 debt tokens
```

Thus:

```text
collateral value / bad debt = 2
```

A post-default entrant spends approximately `B` and receives collateral worth approximately `2B`, giving approximately 100% gross ROI. The test requires more than 90% conservative ROI after rounding and assigns zero value to any residual attacker shares.

## Strong controls in the PoC

### Pre-default ownership control

Immediately after physical delivery, the test snapshots state and lets the original LP call `dealBadDebt(B)`. The original LP receives all recovery collateral. State is then restored.

### Zero-share negative control

The attacker contract attempts `dealBadDebt(B)` before minting shares. The call reverts.

### Post-default capture

The attacker contract mints fresh shares and calls `dealBadDebt(B)` in the same external transaction. It receives exactly the collateral the original LP received in the counterfactual branch.

### Old LP displacement

After the attack:

- the original LP's share balance is unchanged;
- the vault's recovery collateral balance is zero;
- the bad-debt entry is zero;
- the original LP's subsequent `dealBadDebt()` call reverts.

## Why this is not normal recapitalization

A recapitalization mechanism may intentionally exchange fresh debt tokens for distressed collateral. That alone does not justify this implementation's share accounting.

The unsafe property is that the exchange right is represented by ordinary fungible vault shares whose mint price still counts the bad debt at face value but does not include the market value of delivered collateral. A user enters after the result is known and buys the recovery option at a stale accounting price.

The original LP funded the lending position and bore the default risk. The new entrant did neither. Yet the new entrant can consume the entire recovery upside without compensating the original LP at fair value.

## Recommended remediation

A robust fix should do one of the following:

1. recognize the bad-debt loss immediately and include delivered collateral at a defensible value in ERC-4626 accounting;
2. snapshot pre-default share ownership and issue a separate recovery claim;
3. block deposits and mints while bad debt remains outstanding and restrict recovery settlement to shares that existed when bad debt was recognized.

Only adding a reentrancy or same-transaction check is insufficient.
